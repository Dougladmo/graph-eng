**Goal:** Entregar GraphEng 2 nos hosts Claude Code e Codex com execução real, gates independentes, retomada confiável e interface simples.

**Architecture:** Evoluir `workflows/graph-eng.js`, que continua sendo o único controlador do DAG e dos ciclos. O harness atual passa a carregar esse mesmo código no runner Node de produção; adaptadores fornecem agentes, checks, fingerprints e eventos. O Workflow sem Node usa a mesma interface por capacidades explícitas: um host que não consiga executar o serviço confiável de checks bloqueia a implementação, sem confiar no relato de agente.

**Tech Stack:** JavaScript/ESM, Node sem dependências novas de runtime, node:test, CLI oficiais Claude Code/Codex e plugin/skill nativos.

**Spec:** `docs/superpowers/specs/2026-10-17-graph-eng-2.md` (aprovada pelo Douglas).

## Contrato estável entre tarefas

```js
// Tipos JSON: serializáveis e versionados. Nenhuma função entra em args persistidos.
// Role = planner | planReviewer | designReviewer | executor | verifier | critic | synth
// Feedback = {kind: APPROVE|FIX_LOCAL|REPLAN|BLOCK|DONE, reason, severity,
//             affectedNodes: string[], evidenceIds: string[]}
// Event = {schemaVersion:2,runId,seq,at,type,planVersion,nodeId?,payload}
// Handle = {id,role,model}; Result = {status:'ok'|'failed'|'cancelled',output,usage,error?}
// CheckSpec = {id,command,args:string[],cwd,timeoutMs,heavy:boolean}
// Receipt = {id,checkId,identity,exitCode,signal,startedAt,finishedAt,stdoutPath,stderrPath}
// Snapshot = {identity,files:[{path,kind,hash}],inputHash,contractHash}
// Transporte createHost: spawn/wait/cancel/emit conforme implementação efetiva de bin/hosts.mjs.
// Os serviços abaixo pertencem ao runtime do supervisor, não ao transporte:
// capabilities() => Promise<{host,models:string[],spawn,wait,cancel,checks,fingerprint,events,readOnlyEnforced}>
// spawn({role,model,prompt,schema,cwd,writeScope,readOnly,timeoutMs}) => Promise<Handle>
// wait(handle) => Promise<Result>; cancel(handle,{reason}) => Promise<void>
// runChecks({runId,snapshot,checks}) => Promise<Receipt[]>
// fingerprint({cwd,inputs,contracts,outputs,exclude}) => Promise<Snapshot>
// emit(event) => Promise<void>
```

A interface acima é normativa para os serviços do supervisor; ajustar somente o mapeamento do transporte à API real de `bin/hosts.mjs` quando o slice Luna estiver salvo. Não criar campos de schema fictícios para satisfazer testes. `args.hostCapabilities` persistido nunca constitui evidência. Capabilities precisam ser medidas por execução, incluindo o identificador efetivo do modelo; lista estática não comprova disponibilidade. `runChecks` e `fingerprint` são executados pelo processo Node supervisor, nunca por prompt. Se o Dynamic Workflow não permite injetar estas funções, a skill chama `graph-run.mjs --host claude`: esse runner compila o MESMO script Workflow e injeta as funções. Manter a invocação legada apenas para leitura/histórico/planejamento até provar bridge confiável; `implemente` sem capacidade resulta BLOCK. Não criar API HTTP de agentes, SDK pago próprio ou segundo motor.

## Ajustes vinculantes após review Sol — slice2

- Injeção única: global `runtime` e terceiro argumento do harness `{runtime}`. `createHost` é transporte; checks/fingerprints/writeReport são serviços confiáveis do supervisor. `args.hostCapabilities` nunca autoriza execução ou DONE.
- `planOnly` tem precedência sobre mode: `mode:implement, planOnly:true` permite planner e revisão forte read-only, sem executor/polish. Capacidade de evidência ausente bloqueia antes de qualquer executor de produto, depois do ramo planOnly quando necessário.
- Evento canônico v2 `{schemaVersion:2,runId,seq,at,type,planVersion,nodeId?,payload}`: motor fornece planVersion; runner atribui seq/at e persiste uma única sequência. Somente runner projeta aliases legados `key`, `agentId`, `label`, `phase`, `result` na raiz do journal, sem duas fontes de estado.
- Discovery runner no painel pode entrar no slice2. Resume/refazer de run v2 ficam BLOCK até lease e fingerprints da tarefa3 estarem implementados; nunca transformar pronto legado em pronto confiável sem hashes verificados.
- `readOnlyEnforced` obrigatório para planner, planReviewer, designReviewer, verifier, critic e synth. Ausência bloqueia papel, não apenas critic/verifier. Executor é único papel com escrita de produto.
- `bin/hosts.mjs` ainda não estava presente na inspeção de revisão; finalizar nomes/roles/caps contra a API real que Luna entregar, preservando separação transporte/runtime e sem adaptar produção a schema fake.
